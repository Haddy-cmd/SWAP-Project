## 1. Executive summary

- **The system is in good architectural shape.** Layering (thin controllers → services →
  repositories), FormRequest validation, `app/Resources/` shaping, and audit logging are followed
  consistently. Auth endpoints are throttled, and the `?token=` document/avatar smell is **actually
  mitigated** — `DocumentFileController` is policy-checked (owner / supervisor / admin), so a valid
  token alone is not enough (`app/Http/Controllers/Shared/DocumentFileController.php:16,42`).
- **Highest-leverage fix: move uploads to object storage (R2).** The same free-tier ephemerality
  that recently deleted the production *database* also silently drops **every uploaded document,
  avatar, and office logo on each redeploy** (§8, §11.1). Most likely source of quiet data loss in
  normal operation.
- **One real unauthenticated data leak exists and is trivial to close:** the dead `QrCodeController`
  exposes every recipient's name + QR payload by enumeration. Delete it (C1).
- **One production-credential risk:** the admin seeder ships a default password (`SwapAdmin2024`)
  visible in the repo (C2).
- **Test suite is effectively green** (97/99); the 2 failures are time-of-day-flaky interview tests,
  not regressions. The absence of CI (§11.8) is why they flipped red unnoticed.

## 2. Critical / must fix

### C1 — Public, enumerable `QrCodeController` leaks recipient PII + QR payloads

- **Why it matters:** `routes/api.php:51-52` register `/qr-codes/{assignmentId}` and `/…/view`
  **outside any auth group**. `QrCodeController::show` (`QrCodeController.php:22-23`) returns
  `$assignment->user->name` and the raw `qr_code_data` for *any* assignment id. An attacker iterates
  `1,2,3,…` and harvests every recipient's name, academic year, semester, and QR payload. The
  controller is also **dead** (no frontend reference — confirmed by grep) and its hand-rolled
  `encodeQr()` (`QrCodeController.php:153-170`) produces an invalid, unscannable QR (no finder
  patterns / error correction). Real QR generation lives in `QrCodeService`.
- **Approach:** Delete the controller, both routes, and the `use` import (`routes/api.php:6`). No
  replacement needed.
- **Files:** `app/Http/Controllers/QrCodeController.php`, `routes/api.php`.
- **Effort:** S
- **Done-when:** both routes return 404; `php artisan test` green; grep confirms nothing referenced
  them.

### C2 — Default production admin password is committed to the repo

- **Why it matters:** `database/seeders/ProductionAdminSeeder.php:18-22` defaults to
  `admin@msumarawi.edu.ph` / `SwapAdmin2024` when `ADMIN_EMAIL` / `ADMIN_PASSWORD` are unset, and
  `start.sh` runs it on every deploy. Anyone reading the repo has the admin credentials — and unset
  envs are the default. Live on the current service unless those vars are set.
- **Approach:** Add `ADMIN_EMAIL` and `ADMIN_PASSWORD` as `sync: false` vars in `render.yaml` (real
  values set in the dashboard); optionally make the seeder refuse the literal default when
  `APP_ENV=production`.
- **Files:** `render.yaml`, `database/seeders/ProductionAdminSeeder.php`.
- **Effort:** S
- **Done-when:** prod admin login uses a secret not present in git; the two vars are documented in
  `render.yaml`.

### C3 — Corrupt `ApplicationDocument.file_url` rows (masked, not fixed)

- **Why it matters:** `DocumentFileController.php:56` works around stored `file_url` values literally
  containing `{DOC_ID}` or `api/documents`. The read path is defended, but the **stored data is
  still wrong** — any future code path that trusts `file_url` breaks, and the workaround hides the
  blast radius.
- **Approach:** A backfill migration / console command to rewrite corrupt `file_url` to the correct
  stored path (audit-logged); keep the controller guard as defense-in-depth.
- **Files:** new `database/migrations/…_fix_document_file_urls.php` or an `app/Console/Commands/`
  command.
- **Effort:** M
- **Done-when:** `SELECT count(*) FROM application_documents WHERE file_url LIKE '%{DOC_ID}%' OR
  file_url LIKE '%api/documents%'` = 0. *(Verify against real prod data — row count not confirmable
  from a freshly rebuilt DB.)*

## 3. Recommended / should do

### R1 — Move uploads off the ephemeral disk to Cloudflare R2 *(highest leverage)*

- **Why it matters:** §8 / §11.1 — Render's free disk is wiped on redeploy; documents, avatars, and
  office logos disappear. `league/flysystem-aws-s3-v3` is already a dependency.
- **⚠ Documented-decision conflict:** the overview commits to the Render **free tier / public disk**.
  This does not force leaving free hosting — **R2 has a free tier (10 GB)** — but it *is* a
  deliberate change from the documented setup; make it consciously.
- **Approach:** Configure a `documents` disk (R2 creds), point `documents_disk` at it, migrate
  existing files, keep `storage:link` for local dev.
- **Files:** `config/filesystems.php`, `.env` / `render.yaml`, upload call sites (already read
  `config('filesystems.documents_disk')`).
- **Effort:** M
- **Done-when:** upload a document → redeploy → it still loads.

### R2 — Replace `QUEUE_CONNECTION=sync` with an async worker

- **Why it matters:** §9.4 / §11.2 — mail / notifications run on the request path; a provider outage
  becomes a 500 *after* the DB write (the orphan-registration bug). `DEPLOYMENT.md §1` documents the
  worker.
- **⚠ Conflict:** a `worker` service competes for Render free instance hours; note the trade-off.
- **Approach:** `QUEUE_CONNECTION=database`, add the worker service, keep the transaction-wrapping
  pattern for new post-write side effects.
- **Files:** `render.yaml`, `.env`, queue config.
- **Effort:** M
- **Done-when:** registration succeeds with the mail provider down; the email retries asynchronously.

### R3 — Add a CI pipeline

- **Why it matters:** §11.8 — nothing runs the suite / typecheck / build on push. The split-commit
  trap (§9.10) *and today's flaked interview tests* would have been caught. The meta-fix that guards
  everything else.
- **Approach:** GitHub Actions: a Postgres service + `php artisan test`, and `tsc --noEmit` +
  `next build` for the frontend, on PRs.
- **Files:** `.github/workflows/ci.yml`.
- **Effort:** S–M
- **Done-when:** a red build blocks merge; a backend-only change that breaks a rendered field fails
  CI.

### R4 — Throttle the public chatbot endpoint

- **Why it matters:** `routes/api.php:46` — `/chatbot/query` is a public GET with **no throttle**. If
  it hits a paid LLM, a direct cost / DoS vector; even FAQ-backed it is unbounded. Every other public
  endpoint is throttled — this is the one gap.
- **Approach:** Add `->middleware('throttle:20,1')` (tune to the backing cost).
- **Files:** `routes/api.php`.
- **Effort:** S
- **Done-when:** the endpoint rate-limits. *(Confirm whether `query` calls a paid model — that sets
  the real severity.)*
